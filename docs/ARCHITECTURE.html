MockFlow-AI — Architecture (current)

Single source of truth for the current stack, as of 2026-10-06. The older MIGRATION_HISTORY.md and SUPABASE_SCHEMA_HISTORY.md files describe earlier states (Supabase, a planned Xata move) and are kept only for history — do not follow them for setup. DEPLOYMENT.md describes the earlier Fly.io setup; the app no longer runs there.

Stack

Concern Technology
Host One Google Cloud e2-micro VM (Always Free), Docker Compose, Caddy in front for automatic TLS — see DEPLOYMENT_GCP
Web app Flask 3 (app.py), gunicorn (gthread, 1 worker, 8 threads) inside the web container
Voice agent LiveKit Agents (agent_worker.py), one subprocess per interview via worker_manager.py; turn logic in interview_runtime.py, interview_turn.py, interview_coverage.py — see AGENT_DESIGN
Database Neon Postgres (db.py, psycopg3 pool)
Auth Authlib Google OAuth + Flask-Login (auth_helpers.py)
STT / LLM / TTS Deepgram (STT), OpenAI (LLM + TTS) — BYOK: each user supplies their own keys; an optional free tier uses the owner's keys
Key storage Fernet-encrypted in Postgres (ENCRYPTION_KEY)
Code execution Piston, optional, off by default (PISTON_ENABLED)

There is no MongoDB and no Supabase in the running system. supabase_client.py is a thin compatibility shim re-exporting db.db_client under the old name; the live importer is agent_worker.py.

Request flow

Browser ──HTTPS──▶ Caddy (TLS, :443) ──▶ web container (gunicorn, :8080)

Browser (form)  ──POST /api/token──▶  Flask
                                      ├─ load user's encrypted keys from Neon (or the free-tier keys)
                                      ├─ worker_manager.spawn_worker()  ──▶ agent_worker.py subprocess
                                      └─ mint LiveKit JWT ──▶ returned to browser
Browser  ──join LiveKit room──▶  agent_worker (code-owned turn loop)
                                      └─ on end: save interview + coding submissions to Neon
Browser (feedback) ──POST /api/feedback/verdict──▶  Flask ──▶ OpenAI ──▶ verdict

The per-track interview state (fsm.py) covers intro, behavioral, technical_voice and coding (see tracks/). Stage changes are decided in code, not by the model.

Environment variables

The app reads these (see env.template):

  • Required: DATABASE_URL, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, SECRET_KEY, ENCRYPTION_KEY
  • Optional: FLASK_ENV, CORS_ORIGINS, MAX_CONCURRENT_WORKERS, the free-tier block (FREE_TIER_ENABLED, SYSTEM_*), PISTON_*
  • Per-user (not env): LiveKit / OpenAI / Deepgram keys — entered in the app, stored encrypted.
  • Worker subprocess only (injected by worker_manager): LIVEKIT_URL/API_KEY/API_SECRET, OPENAI_API_KEY, DEEPGRAM_API_KEY, INTERVIEW_ROOM_NAME.

On the VM the secrets live in /opt/mockflow/app.env (root-owned, mode 600), outside the repo, and are passed to the web container via env_file.

Local development

python -m venv .venv && .venv\Scripts\activate    # Windows (use source .venv/bin/activate on *nix)
pip install -r requirements-dev.txt
cp env.template .env                               # then fill in the 5 required vars
psql "$DATABASE_URL" -f migrations/001_initial_schema.sql
python app.py                                      # http://localhost:5000

Run the test suite and linter:

python -m pytest
python -m ruff check .

Deployment (Google Cloud e2-micro)

  • Containers: deploy/gcp/docker-compose.yml runs web (built from the repo's Dockerfile) and caddy (caddy:2-alpine, deploy/gcp/Caddyfile). Only Caddy publishes ports (80 for the ACME challenge, 443).
  • Start command (in the Dockerfile): gunicorn app:app --worker-class gthread --workers 1 --threads 8 --timeout 120. --workers 1 is required: active agent subprocesses live in one process's memory.
  • Capacity: MAX_CONCURRENT_WORKERS=1 and mem_limit: 768m — the VM has 1 GB and each interview's agent loads Silero VAD.
  • Deploying is manual. A push does not deploy. On the VM: cd ~/MockFlow-AI && git pull && cd deploy/gcp && docker compose up -d --build.
  • Health: GET /health pings Neon and reports worker load; the container healthcheck calls it every 60 s.
  • CI (.github/workflows/deploy.yml) runs ruff and pytest on every push and checks the live site still answers; it does not deploy.
  • Keep-warm: .github/workflows/keep-warm.yml keeps Neon's free tier from suspending; the web container itself is always on.
